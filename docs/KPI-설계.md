# 공공·SI·SM UI·UX KPI 시안

2026-11-20 조사. 아래 항목은 공식 자료의 서비스요청 처리·검수·사용성·접근성·호환성 관리 관점을 WorkLog에 맞춰 **직접 구성한 제안**입니다. 개별 기관이 이 10개 항목이나 목표값을 그대로 사용한다는 뜻이 아닙니다. 계약 SLA와 조직의 승인 기준이 확정되기 전에는 성과평가 점수로 사용하지 않습니다.

| 구분 | KPI | 제안 목표 | 근거로 참고한 업무 관점 |
|---|---|---|---|
| 공통 | 요청 처리 완료율 | 90% 이상 | 서비스요청 처리 현황 |
| 공통 | 납기 준수율 | 95% 이상 | 서비스요청 적기 처리 |
| 공통 | 평균 작업 소요일 | 5일 이하 | 처리 소요기간 관리. 시작·완료일 포함 달력일 |
| 공통 | 지연 과업 비율 | 10% 이하 | 기한이 지난 미완료 요청 관리 |
| 기획 | 요구사항 반영률 | 100% | 요구사항추적표와 설계·구현·검수 연결 |
| 기획 | 설계 산출물 1차 승인율 | 90% 이상 | 정책·화면설계서 검토와 승인 |
| 디자인 | 디자인 가이드 준수율 | 95% 이상 | KRDS·디자인 시스템·컴포넌트 일관성 |
| 디자인 | 디자인 시안 1차 승인율 | 85% 이상 | 시안 제출·발주처 검토·수정·승인 |
| 퍼블리싱 | 접근성 점검 통과율 | 100% | 키보드, 초점, 대체텍스트, 명도 대비 등 자체 점검 |
| 퍼블리싱 | 반응형·호환성 검증 통과율 | 98% 이상 | 화면 × 기기 × 브라우저의 합의된 시험 시나리오 |

목표값은 UI 검토를 위한 가정입니다. 출처의 수치를 인용한 것이 아닙니다. 최초 승인율에는 요구사항 확정 후 변경 요청을 구분하는 합의가 필요합니다. 가이드 준수율은 프로젝트에 적용하기로 합의한 가이드 버전과 점검 항목을 기준으로 측정해야 합니다. 접근성 비율은 자체 점검 통과 비율이며 공인 인증 점수나 인증 획득 여부를 의미하지 않습니다. 아직 시험하지 않은 항목과 적용 제외 항목은 통과로 간주하지 않습니다.

## 실제 데이터와 샘플

- 기본은 사용자가 요청한 검토용 ‘샘플 보기’입니다. 모든 값에 샘플임을 표시합니다. 가상 과업 12개의 담당 업무 36건과 별도 검수·점검 예시를 사용합니다.
- ‘업무 데이터’에서는 업무관리·조회보고와 같은 고객 원본 과업을 읽습니다. 원본과 내부 수정값이 다르면 원본 값을 기준으로 합니다. 원본 목록에서 제외된 과업은 KPI 대상에서 제외합니다.
- 배정된 기획·디자인·퍼블리싱 업무 한 개를 한 건으로 셉니다. 공동 담당자가 여러 명이어도 인원수만큼 중복 계산하지 않습니다.
- 완료 상태는 ‘완료’ 또는 ‘운영반영완료’입니다. ‘완료 후 수정’은 현재 미완료 업무로 집계합니다. 이는 현재 스냅샷 지표이며 기간 내 누적 처리 실적과 다릅니다.
- 납기·소요일은 원본의 파트별 시작·완료 필드 또는 작업내용에 명시된 날짜만 사용합니다. 시작일은 첫 줄의 `작업시작일자: YYYY-MM-DD`, 완료일은 `작업종료일자: YYYY-MM-DD`도 읽습니다. 시작·완료 관측 시각이나 오늘 날짜로 누락 일자를 추정하지 않습니다.
- 날짜를 확인할 수 없는 건은 해당 계산에서 제외하며 카드에 집계 건수를 표시합니다. 미래 완료일과 잘못된 날짜는 집계하지 않습니다. 분모가 0이면 0%나 100%가 아닌 집계 대기입니다.
- 실제 승인·검수·점검 원장이 없는 품질 지표 6개는 집계 대기로 남깁니다. 샘플 수치가 실제 점수로 섞이지 않습니다. 별도 품질 기록 입력·저장 기능은 이번 시안에 포함하지 않았습니다.
- 샘플은 `test/kpi-samples.js`, 화면·산식·참고자료는 `source/html/reports/kpi-dashboard.js`, 스타일은 같은 폴더 `style.css`에 있습니다. 샘플은 고객 JSON, 공용 save, 개인 저장에 합치지 않습니다.
