# UI·UX 업무관리

2026-11-23 기획서의 요청관리 대시보드 / 기획 / 디자인 / 퍼블 4열을 사용합니다. 상태·작업자 필터는 열마다 독립적이며 처음에는 진행중입니다. 진행중에는 접수·작업중·완료 대기·개발 반영 단계가 포함됩니다. 완료 카드는 회색, 운영 반영 카드는 진한색으로 표시하며 운영 반영·보류·반려는 전체 표시 또는 해당 상태에서 조회합니다.

각 역할의 완료 버튼은 본인 담당 업무만 변경합니다. 완료 후 수정 버튼은 수정 작업으로 되돌리며 기존 완료 날짜를 보존합니다. 요청된 모든 역할이 완료되면 참여자가 개발 반영 주소를 등록할 수 있고, 그다음 운영 반영을 등록합니다. 반영은 실제 서버 배포 명령이 아니라 반영 URL·처리자·시간의 기록입니다. 수정 작업으로 되돌리면 현재 반영 단계를 해제하며 이전 반영 주소는 타임라인에 남습니다.

담당자 추가 시 확인한 날짜를 시작일로 기록합니다. 과거 고객 자료의 최초 배정일은 첫 관찰 이전으로 추정하지 않습니다. 본인의 시작일은 상세창에서 수정할 수 있습니다. 완료일은 완료 버튼을 누른 날짜입니다.

신규 등록은 자체등록 배지로 구분합니다. 요청구분(기획·디자인·퍼블·기타), PC·MO, 적용서비스, 요청팀·요청자, 요청일·완료요청일, 요청명·배경·사항, 작업자·작업내용, 산출물 폴더, 전달 링크와 첨부파일을 저장합니다. 기타는 `workflow.etc=true`입니다. 역할을 선택하고 작업자를 배정하면 해당 열에도 표시됩니다. 주간·월간 일정 버튼은 4열을 유지하면서 이번 주·이번 달의 완료요청일 범위로 조회합니다. 날짜 초기화로 기간 제한을 해제합니다. 같은 과업 ID로 조회·보고 화면에 연결됩니다.

고객 원본 JSON은 읽기만 합니다. 추가 내용은 WorkLog 과업의 `workflow`와 `overrides`에 저장되며 기존 process/work 저장 및 충돌 보호 절차를 따릅니다. 완료만 기록한 경우 다음 원본 읽기에서 다른 담당자의 최신 배정·내용·상태를 계속 반영합니다. 과업 정보 수정에서 명시적으로 편집한 항목은 WorkLog 수정값으로 유지합니다. 댓글 작성자는 현재 로그인 사용자이며 본인 댓글만 수정·삭제합니다.

파일은 기존 게시판 첨부 검증을 재사용합니다(파일당 20MB, 합계 40MB, 최대 10개). 링크는 HTTP(S), file URL, Windows 드라이브/공유 경로만 허용합니다. HTTPS 페이지에서 file 링크를 여는 동작은 Edge 보안 정책에 제한될 수 있으므로 실제 내부망 Edge 환경에서 허용된 파일 경로로 확인해야 합니다. 브라우저 보안 해제는 사용하지 않습니다.

수정 위치:

- `source/html/work/uiux/model.js`: 상태, 권한, 저장·검증
- `source/html/work/uiux/page.js`: 카드·등록·상세 화면
- `source/html/work/uiux/style.css`: 화면 스타일
- `source/js/app.js`: 공통 로그인·화면·저장과의 연결
- `test/uiux-workflow.test.cjs`: 원본 보호, 완료·반영·댓글·재조회 검증
