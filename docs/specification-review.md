# 2026-11-23 기획서 대조

적용 위치는 UI·UX 사진 6장의 내용은 `업무관리 → UI·UX`, 퍼블리싱 문서 사진 2장의 내용은 `업무관리 → 퍼블리싱 문서`입니다. 콘텐츠·퍼블리싱 문서·오류개선 화면을 합치지 않습니다.

## UI·UX

| 항목 | 반영 기준 |
|---|---|
| 4열 | 요청관리 대시보드 / 기획 / 디자인 / 퍼블 |
| 보기 버튼 | 카드·도표 토글 바로 옆 주간 일정 / 월간 일정 |
| 상태 필터 | 열별 독립, 진행중 기본, 전체 표시·개발반영·운영반영완료·보류·반려 |
| 작업자 필터 | 기획·디자인·퍼블 열에 각각 제공 |
| 대시보드 카드 | 상태·요청구분, 밑줄 제목, 요청자·요청팀, 요청일·완료요청일 |
| 완료 표현 | 담당 업무 완료는 회색, 운영반영완료는 진한 배경 |
| 반영 | 요청된 디자인·퍼블 완료 후 개발 반영 주소 입력, 이후 운영 반영 |
| 운영 우선 | 운영반영완료가 다른 단계보다 우선, 전체 표시에서 먼저 배치 |
| 담당 카드 | 완료·수정 토글, 우측 담당자 프로필·이름 |
| 작업 링크 | 여러 개, 길어지면 가로 스크롤 |
| 반영 링크 | 담당 열 하단에서 해당 반영 주소 열기 |
| 신규 등록 | 대시보드 하단, 별도 상단 등록 버튼 제거 |
| 신규 등록 항목 | 요청구분 / 사용대상 / 적용서비스 / 요청팀·요청자 / 요청일·완료요청일 / 요청명·배경·사항 / 첨부 |
| 자체등록 | 자체등록 배지, 기타 선택 시 etc=true |
| 자체 과업 제목 | 상태 추가·작업자·파트별 내용 수정 화면 |
| 시작·완료 | 배정 관찰 날짜를 시작일로 기록·본인 수정, 완료 클릭 날짜를 완료일로 기록 |
| 상세 본문 | 파트별 작업내용 / 요청배경 / 요청사항 / 산출물 결과 폴더 / 작성기 연동 링크 |
| 댓글 | 로그인 작성자, 입력·본인 수정·삭제 |
| 타임라인 | 사용자의 후속 지시에 따라 댓글 아래 세로 배치 |
| 본인 권한 | 다른 담당자의 실제 진행 상태를 바꾸지 않음, 실제 저장 로직에서도 검사 |

## 퍼블리싱 문서

| 항목 | 반영 기준 |
|---|---|
| 보기 탭 | 과업별 / 전체목록 |
| 과업별 열 | 과업명 / 디자인 / 퍼블 / 마감일 / 개발배포 / 산출물 / LINK |
| 등록 | 표 아래 1뎁스·2뎁스·3뎁스 선택 + 등록 |
| 등록 후 표시 | 등록 → ○ |
| 개발배포 | 주소 값이 있을 때 LINK 버튼 |
| 운영배포완료 | 두 목록에서 제외, 저장 자료는 보존 |
| 전체목록 열 | 1뎁스 / 2뎁스 / 3뎁스 / 과업명 / LINK |
| 계층 | 상위 메뉴별 병합, 메뉴없음은 마지막 |
| 데이터 | 동일 과업 ID로 UI·UX 연결, 원본 수정 금지 |

## 시뮬레이션

`test/specification-scenarios.test.cjs`에서 5개 상태 × 4개 담당 업무 구성 × 5개 메뉴 경로의 서로 다른 **100개 조합**을 검증합니다. 단순히 같은 테스트를 100회 실행한 수치가 아닙니다.

각 조합에서 4열 순서·독립 필터·상세 항목·댓글과 타임라인 순서·본인 상태 변경 권한·운영완료 제외·산출물 등록 표시·개발배포 주소 조건·전체목록 분류·저장 복원·고객 원본 불변 여부를 확인합니다. 별도 테스트로 메뉴 병합, 잘못된 URL, 최신 원본 재가져오기, 공용 저장, 독립창 리소스 제공도 확인합니다.
