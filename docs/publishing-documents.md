# 퍼블리싱 문서

업무관리 → 퍼블리싱 문서에만 표시합니다. UI·UX의 동일한 과업 ID를 사용하며 고객 원본 JSON을 쓰거나 이동하지 않습니다.

## 과업별

표 열은 **과업명 / 디자인 / 퍼블 / 마감일 / 개발배포 / 산출물 / LINK** 순서입니다. 담당자 순서는 조직도 순서를 따릅니다. 마감일은 원본의 완료요청일입니다. 운영반영완료·운영배포완료 과업은 표시 대상에서 제외합니다.

개발배포 열과 LINK 열에 각각 추가 버튼이 있습니다. 이름과 주소를 여러 행으로 추가·수정·삭제하고 등록합니다. 원본의 `개발반영URL`, `개발배포URL`, `개발반영`, `개발배포`와 UI·UX에서 기록한 반영 URL을 초기값으로 읽으며 고객 원본을 수정하지 않습니다. 문서에서 링크를 등록해도 담당자의 진행 상태나 실제 배포 단계는 바뀌지 않습니다.

산출물의 등록 버튼을 누르면 표 아래에 **산출물 등록** 영역을 엽니다. 1뎁스 → 2뎁스 → 3뎁스 순서로 선택하고 등록합니다. 상위 메뉴를 바꾸면 하위 선택을 초기화합니다. 메뉴없음을 선택하면 하위 메뉴를 비우고 비활성화합니다. 고객 데이터나 기존 등록 내용에 없는 메뉴는 직접 입력할 수 있습니다. 임의의 실제 메뉴를 생성하지 않습니다. 개발 샘플의 메뉴 목록은 실제 데이터 연결에 섞지 않습니다.

산출물에는 이름·주소·Windows 파일 경로를 여러 개 등록하거나 파일 여러 개를 첨부할 수 있습니다. 이미지·동영상·ZIP·문서를 지원하며 파일당 20MB, 전체 40MB, 최대 10개입니다. 기존 파일의 유지 체크를 해제하면 다음 등록에서 해당 첨부를 제거합니다. 파일·주소 산출물이 있으면 메뉴를 고르지 않아도 메뉴없음으로 등록할 수 있습니다.

산출물 등록 성공 후 버튼은 **○**로 바뀌며 다시 누르면 수정할 수 있습니다. 개발배포나 일반 링크만 등록한 경우 산출물 표시를 변경하지 않습니다. 각 항목을 수정해도 나머지 링크·첨부는 보존합니다.

## 전체목록

표 열은 **1뎁스 / 2뎁스 / 3뎁스 / 과업명 / LINK** 순서입니다. 등록된 과업만 표시하고, 같은 상위 메뉴는 세로로 합칩니다. 메뉴없음은 마지막에 둡니다. 운영배포가 완료된 과업은 여기서도 제외합니다. 저장된 산출물 자료는 삭제하지 않습니다.

## 저장과 수정 위치

등록 내용은 WorkLog 과업의 `workflow.publication`에 저장합니다. 원본 과업은 `overrides.workflow.publication`으로 분리하며 기존 공용 저장·충돌 보호를 사용합니다. 고객 원본 재가져오기와 과업명 변경 이후에도 동일 ID의 산출물 등록을 보존합니다. 시작일·진행률·담당자의 완료 상태를 바꾸지 않습니다.

- `source/html/work/publishing-docs/model.js`: 원본 연결·제외 조건·계층·등록 검증
- `source/html/work/publishing-docs/page.js`: 두 표와 등록 영역
- `source/html/work/publishing-docs/style.css`: 전용 스타일
- `test/publishing-docs-samples.js`: 삭제 가능한 개발 샘플
- `test/specification-scenarios.test.cjs`: 100개 상태 조합 및 추가 경계 조건

HTTP(S)와 Windows 파일 경로를 허용합니다. file 링크를 여는 동작은 내부망 Edge의 정책에 따르며 보안 해제를 사용하지 않습니다.
