# WorkLog

## 폴더 구성

- `source/html`: 실제 페이지. `source/js`, `source/css`, `source/images`, `source/font`: 로컬 화면 리소스.
- `test`: 개발 샘플, 샘플 생성 도구, 자동 테스트. `test/results`: 검증 결과. 개발 중에는 샘플을 유지합니다.
- `process`: 고객 원본과 분리한 변경 불가능한 저장 목록. 기능별 실제 데이터는 `save`에 저장합니다. `process/legacy`는 이전 통합관리 JSON과 백업입니다.
- `save/게시판/`: 게시글과 댓글을 글 하나당 JSON 파일 하나로 저장합니다. 글을 수정하면 새 버전을 남깁니다.
- `save/휴가/<연도>/`: 휴가 시작 연도별 기록과 해당 연도의 개인별 연차 총수를 JSON으로 저장합니다. 연말을 걸치는 휴가는 시작 연도에 보관하고 조회 시 전체 기간을 반영합니다.
- `save/휴가/설정/`: 휴가 유형과 근속연수별 연차 정책을 저장합니다. 내년 연차 선사용은 실제 휴가일의 다음 연차 연도에서 차감하며, 휴가 기록은 실제 시작 연도 폴더에 보관합니다.

연차 정책은 근속연수 범위와 마지막 최대 부여 구간으로 설정합니다. 법정 기본값은 1~2년 15일, 3~4년 16일이며 이후 2년마다 1일씩 가산해 21년 이상 25일입니다. 입사 1년 미만은 완료된 개근 월마다 1일씩 최대 11일을 계산합니다. 자동 계산은 출근율 80% 이상과 매월 개근을 전제로 한 기본 부여량입니다. 개인별 직접 입력한 연차 총수를 우선하며, 실제 근태·단시간 근로·휴직·소멸 및 이월 조건은 해당 총수로 반영합니다. [근로기준법 제60조](https://www.law.go.kr/lsLinkProc.do?joNo=006000&lsNm=%EA%B7%BC%EB%A1%9C%EA%B8%B0%EC%A4%80%EB%B2%95&mode=11), [고용노동부 연차휴가 안내](https://1350.moel.go.kr/rtmview.do?id=1000325013).
- `save/users/<사용자 이름>/`: 사용자별 개인 메모·일정의 저장 이력. 이름은 경로에 안전한 형태로 인코딩됩니다.
- `data/request/<최초 요청 ID>/`: 업무요청, 확인, 수정, 전달 이력. 한 요청의 모든 회신을 같은 폴더에 추가 저장합니다.
- `prg`: Edge 독립창 실행, 바로가기, 로컬 서버, 복구·배포 도구. 배포 ZIP은 `prg/releases`.
- `docs`: 사용 방법과 개발·디자인 문서.
- 루트는 실행용 `index.html`과 Git 동작에 필요한 `.gitignore`, `.nojekyll`만 유지합니다. Git 내부 폴더는 숨김 폴더입니다.

고객 원본 JSON은 읽기 전용입니다. 원본 폴더 또는 그 하위 폴더를 저장 위치로 선택할 수 없습니다. 원본 파일은 수정·삭제·이동하지 않습니다. 저장 폴더에는 **프로젝트/공용 저장의 최상위 폴더**를 선택하세요. 프로그램이 그 아래 `process`, `save`, `data`를 나눠 관리합니다. 이 경로와 이전 이력이 들어 있는 `dist`를 함께 백업하세요.

## Windows 10/11 실행

1. 전체 프로젝트를 고정된 위치에 압축 해제합니다.
2. `prg/Create-Desktop-Shortcut.bat`를 실행하면 바탕화면 바로가기를 만듭니다.
3. 바로가기 또는 `prg/Start-WorkLog.bat`로 Edge 앱 창을 실행합니다. 주소 표시줄이나 탭은 표시되지 않습니다.
4. 폴더를 옮긴 뒤에는 바로가기 생성 파일을 다시 실행하세요. 기존 버전의 로컬 서버가 열려 있다면 종료 후 새 버전을 실행하세요.

기본 실행은 Windows PowerShell/.NET의 읽기 전용 로컬 서버 `http://127.0.0.1:49271/source/html/index.html`을 사용합니다. 별도 런타임 설치나 관리자 권한은 필요하지 않습니다. 보안 정책에서 PowerShell·폴더 접근을 차단하면 사내 HTTPS 서버를 사용해야 합니다. `prg/scripts/Start-WorkLog.ps1 -Mode File`도 제공하지만 file 모드에서는 브라우저 정책에 따라 폴더 연결 기능이 제한될 수 있습니다. 브라우저 보안을 해제하는 옵션은 사용하지 않습니다.

아이콘은 `source/images/ico/WorkLog.ico`입니다. 바탕화면 바로가기에 적용하며 웹페이지 favicon으로도 연결합니다. 작업 표시줄 고정은 Edge/Windows 정책에 따라 다르고, 실행 창 아이콘이 Edge 아이콘으로 보일 수도 있습니다.

화면 리소스는 실행 시 현재 프로젝트 위치를 기준으로 **절대 URL**을 계산합니다. C 드라이브 경로를 다른 PC에 강제로 고정하지 않습니다. CSS의 폰트·이미지 참조도 해당 스타일시트의 절대 URL 기준으로 브라우저가 해석합니다. CDN이나 외부 디자인 프레임워크는 사용하지 않습니다.

## 원본 읽기와 안전한 공용 저장

폴더 연결 시 원본을 읽고, 저장 폴더의 최신 이력을 읽어 반영합니다. 원본 변경을 즉시 감시하는 방식은 아니며 새로고침/원본 새로 읽기로 다시 확인할 수 있습니다. 기존 사용자 수정값과 가져온 원본을 구분해 유지합니다.

`내용 저장`은 `save`의 기능별 파일, `save/users`의 사용자별 파일, `save/게시판`의 게시글별 파일을 작성한 뒤 process/commits에 최종 이력을 발행합니다. 변경하지 않은 파일은 재사용합니다. 이전 방식으로 저장한 게시판 데이터는 다음 저장부터 `save/게시판`에 글별로 기록합니다. 이전 save/commits와 통합관리 JSON은 읽기만 합니다. 이전 dist/users 이력은 계속 읽을 수 있으며, 새 저장부터 사용자별 JSON은 save/users에 기록합니다. 기존 JSON 백업을 process/legacy에 둔 경우에도 읽을 수 있습니다.

동시에 저장하면 기존 버전과 다른지 검사합니다. 충돌한 양쪽 이력은 삭제하지 않고 추가 저장을 중단합니다. 복구 시 모두 편집을 멈춘 후 `prg/scripts/Recover-Save.ps1 -SaveFolder <절대 process 경로>`로 분기를 확인하고 `-Commit <ID>`로 선택합니다. 복구 도구는 모든 분기를 process/recovery에 내보내며 게시판과 현재·이전 개인 저장 경로를 함께 읽습니다. 원본 고객 자료와 기존 이력은 수정하지 않습니다.

업무요청은 일반 업무 저장과 별도로 즉시 저장합니다. UUID별 개별 파일로 추가하므로 서로 다른 사람의 동시 회신을 덮어쓰지 않습니다. 이전 process/requests 또는 save/requests가 있으면 읽기 전용으로 함께 표시합니다. 공유 폴더 권한이 있는 사람에게 파일 수준의 접근권한이 생기며, 웹페이지 로그인만으로 파일 자체의 보안을 제공하지는 않습니다.

## 업무요청

- 요청사항은 전체/받은 요청/보낸 요청, 이름·제목·내용 검색, 최신순/과거순 정렬을 제공합니다.
- 왼쪽 작은 별로 즐겨찾기하면 최상단에 표시됩니다. 오른쪽 삭제는 본인의 요청 목록에서만 숨기며 다른 사람과 공용 이력은 유지합니다.
- 요청 확인 시 해당 과업의 확인한 알림이 해제되고 읽은 카드는 회색으로 표시됩니다. 읽음·숨김·즐겨찾기는 브라우저 내 사용자별로 보관됩니다.
- 작성창은 단계/제목 → 팀별 받는 사람 → 내용 → 여러 확인 URL 순서입니다. 받는 사람은 기획/퍼블/디자인/콘텐츠 순이며 직급순·같은 직급은 가나다순입니다.
- 작업 요청/확인 요청/수정 전달/확인 완료/고객 전달을 기록합니다. 같은 과업에 기획·디자인이 각각 회신해도 한 타임라인에서 확인합니다. 고객 전달은 기록 기능이며 실제 고객에게 파일을 보내지는 않습니다.
- URL은 이름과 http/https 주소를 최대 20개 등록합니다. localhost 주소는 보는 사람의 PC를 가리키므로 팀 확인용이면 모두 접근 가능한 내부 서버 주소를 사용하세요.
- 타임라인은 기본 최신순이며 과거순으로 전환할 수 있습니다. 프로필은 현재 선택 이미지와 연동합니다. 약 3초마다 요청을 확인하지만 내용이 같으면 화면을 다시 그리지 않고, 새 내용이 생겨도 스크롤 위치를 보존합니다.
- 샘플 요청은 [샘플]로 표시하며 실제 공유 폴더에 자동 전송하지 않습니다. 샘플 이력을 실제 전송으로 전달하지 않습니다.

## 화면과 권한

첫 화면은 홈입니다. 큰 페이지 제목 영역을 없애고 필요한 작업 버튼만 유지합니다. 홈 달력에는 본인 프로젝트와 개인 일정이 표시되며 전체/프로젝트/개인메모 필터를 제공합니다. 진행 중 과업과 나의 일정은 약 3개 분량 높이이며 업무 표 안쪽에만 스크롤을 둡니다. 팀 브리핑은 고정된 영역 안에서 내용을 자연스럽게 표시합니다.

브리핑 오른쪽 아래를 다섯 번 클릭하면 색상·크기·위치·좌우반전·X/Y/Z 회전을 미리보고 조정합니다. 사용자·캐릭터·기본형/대두형별로 브라우저에 독립 저장합니다. 모드를 바꿔도 제목/버튼 좌표는 같습니다.

전체관리자 설정에서 직급 추가·이름 변경·제거·순서 조정이 가능합니다. 직급 이름을 바꾸면 해당 인원에도 반영하고, 제거한 직급은 미지정으로 표시합니다. 내용 저장으로 공용 반영하세요. 진행률·상태는 관리자를 포함해 본인 담당 업무만 바꿀 수 있습니다.

접속 프로필은 공용 저장 폴더의 별도 임시 접속 파일을 사용합니다. 업무관리의 다른 사람 커서는 같은 보기·검색 조건에서 약 1.5초 간격으로 표시합니다. 공용 폴더/네트워크·브라우저 백그라운드 상태에 따라 지연될 수 있으며 실시간 서버처럼 매 프레임 동기화되지는 않습니다.

WBS는 사용자 요청으로 보류했습니다.

## 개발 검증과 배포

프로젝트 루트에서 `node --test test/*.test.cjs`로 검증합니다. Node는 개발 검증용이며 실제 사용자는 설치할 필요가 없습니다. 개발 서버는 `node prg/server.cjs` 또는 `npm --prefix prg start`입니다.

배포 파일: `powershell -NoProfile -File prg/scripts/package-offline.ps1`. 결과는 `prg/releases/WorkLog-offline.zip`이며 process/save/dist/data의 실제 데이터, 백업, 계정, Git 이력은 포함하지 않습니다. 개발 확인용 샘플 스크립트는 test 아래에 포함됩니다. 사용자가 요청하기 전까지 개발 샘플을 제거하지 않습니다. 이후 test를 제거해도 기본 앱은 실행됩니다.

Git에는 검증 완료한 소스만 커밋/푸시합니다. process, dist, data, save, 샘플 JSON, 로컬 백업은 제외합니다. 로컬 서버도 해당 저장 폴더와 JSON을 HTTP로 제공하지 않습니다.

## 과업 요청과 내부망 DB 이관

업무요청에서 업무관리 과업을 선택하면 본인에게 보이는 연결 요청과 전송 이력이 표시됩니다. 새 요청은 선택한 과업이 기본값이며, 회신과 전달은 원래 과업 연결을 이어받습니다. 과업 연결이 없는 이전 요청은 전체 요청에서 볼 수 있습니다.

내부망 DB를 붙일 때는 업무관리 과업 ID를 `projects.id`로 유지하고, 요청의 `projectId`를 과업 외래 키로 사용합니다. 요청의 `id`, `rootId`, `parentId`는 각각 메시지 ID, 최초 요청 ID, 바로 앞 메시지 ID입니다. 수신자 목록은 별도 연결 테이블로, 링크는 요청 ID에 연결된 테이블로 옮길 수 있습니다. 과업이 연결되지 않은 기존 요청은 과업 외래 키를 비워 둡니다. 개인 메모와 일정은 사용자별 JSON 이력의 최신 데이터를 사용자 ID와 연결해 이관합니다.

브라우저는 내부 API를 호출하고, 서버에서 사용자 권한을 검사한 뒤 DB에 저장하는 구조를 권장합니다. 현재 버전의 저장 방식은 내부망 공용 폴더입니다. DB 제품, 서버 환경, 인증 방식이 정해지면 해당 환경에서 스키마·API·이관 도구를 구현할 수 있습니다.

## 4열 업무관리와 담당자 시작일

업무관리 기본 화면은 대시보드, 기획, 디자인, 퍼블 순서입니다. 실사용 4열에는 고객 원본 요청을 표시하고, 주차별·진행별에서는 내부에 추가한 과업도 확인할 수 있습니다. 4열 카드의 제목·고객명·완료요청일·상태는 원문 값을 읽습니다. 완료와 개발·운영 반영 이력은 내부 저장에 기록합니다.

원본 폴더 연결이 유효하면 앱 시작 시와 로그인·업무관리 진입 시 고객 요청을 다시 읽습니다. 이전에 읽은 원본과 파트별 담당자를 비교해 새로 나타난 담당자의 작업시작일을 처음 확인한 날짜로 기록합니다. 첫 원본에 이미 있던 담당자의 날짜는 추정하지 않습니다. 팀원끼리 시작일과 내부 변경사항을 공유하려면 공용 폴더에 내용 저장을 하세요.

## UIUX 업무관리와 주간 업무

- 업무관리 아래 UIUX와 콘텐츠 메뉴가 있습니다. UIUX는 고객 원본을 대시보드 / 기획 / 디자인 / 퍼블 4열로 표시합니다. 콘텐츠는 자료 연결 전까지 빈 화면입니다.
- 주간 업무는 완료요청일 기준으로 원본 과업을 주차별 도표로 표시합니다. 과업명을 열면 원본의 이전 값과 바뀐 값을 날짜순으로 확인할 수 있습니다.
- 첫 원본을 비교 기준으로 삼습니다. 타임라인 날짜는 변경을 확인한 날이며, 고객이 실제로 수정한 시각은 원본에 별도 기록이 있어야 확인할 수 있습니다. 누적 이력을 공유하려면 내용 저장을 사용합니다.
- 업무요청 메뉴와 알림을 종료했습니다. 기존 업무요청 파일은 그대로 보관합니다.

### 법인카드 사용내역

조직관리의 법인카드 사용내역에서 카드별로 연도·월을 선택합니다. 전체관리자는 카드 종류를 만들고 월 금액을 설정할 수 있습니다. 기본 금액 변경은 적용 월부터 이후 모든 달에 반영되며, 추가 금액은 설정한 달에만 더합니다. 합계에서 제외한 내역은 목록에 남고 사용액 및 잔액에는 반영하지 않습니다. 이번 달 잔액은 입력한 내역으로 즉시 계산합니다. 내용 저장을 누르면 `save/cards/`에 공용 이력으로 저장합니다.

## 바탕화면 독립 위젯

위젯은 WorkLog 페이지 내부 모달이 아닌 별도 Edge 앱 창입니다. `prg/Start-Widget.bat`을 실행하면 주소창·탭 없는 작은 위젯 창을 엽니다. 메인 WorkLog 창과 별도로 이동하거나 닫을 수 있습니다. 기존 Windows·Edge·PowerShell을 사용하며 별도 런타임 설치는 필요하지 않습니다. ICO와 로고는 프로젝트의 WorkLog 에셋을 사용합니다.

상단의 독립 창 모양 위젯 버튼을 누르면 작은 별도 창을 엽니다. `http://127.0.0.1:49271`에서는 Edge 앱 실행기를 우선 사용합니다. GitHub 웹페이지·`file://`·개발 미리보기 또는 이전 로컬 실행기에서는 브라우저의 작은 독립 창으로 엽니다. 이미 연 브라우저 위젯 창이 있으면 그 창으로 이동합니다. 브라우저 창에는 브라우저 정책에 따른 주소 표시가 남을 수 있으며, 주소창 없는 Edge 앱 창은 로컬 실행기 또는 `Start-Widget.bat`으로 실행합니다. 팝업이 차단되면 차단 안내를 표시하고 버튼을 다시 사용할 수 있게 복구합니다.

화면은 `source/html/widgets/`에서 관리합니다. 표시 방식은 사용자가 선택한 **이동 가능한 작은 독립 창**입니다. 아직 위젯 종류와 데이터 연결은 추가하지 않았습니다. 다른 창 위에 항상 표시하거나 바탕화면 레이어에 고정하지 않습니다.

로컬 실행 요청은 루프백 호스트·같은 출처·전용 요청 헤더·본문 없는 POST만 허용합니다. 외부 URL이나 임의 실행 명령을 받지 않습니다. 원본 JSON과 저장 데이터를 읽거나 쓰는 API는 추가하지 않습니다.

## 장난감

메뉴 순서는 끝말잇기 → 투표 → 돌림판 → 오늘의 식사추천입니다.

- 끝말잇기: 로그인한 누구나 워크로그에서 이어갑니다. 참가자 설정이나 고정 순서는 없으며 작성자는 현재 로그인 이름으로 기록합니다. 기록마다 현재 프로필 캐릭터·이름·날짜·시간과 오른쪽 단어를 한 줄로 표시하고, 한글 2~6글자·중복·두음법칙을 확인합니다. 외부 사전을 사용하지 않아 실제 단어 여부는 참가자가 확인합니다. 마지막 작성자 또는 관리자만 한 수 되돌릴 수 있고 시작 단어는 제거할 수 없습니다. 이전 방식의 게임 기록은 legacyGame에 보존합니다. 단어 수 제한 없이 이어가며 화면에는 최근 100개와 더보기를 제공합니다. 포기 버튼은 확인 후 본인의 포기 횟수를 1회, 직전 단어 작성자가 다른 사람이면 해당 작성자의 kill을 1회 올립니다. 자기 단어에서 포기하면 kill은 올리지 않습니다. 워크로그에서 새 판을 시작하며 이전 판 전체 단어와 포기 내역은 rounds에 보존합니다. 점수는 이 기록으로 계산하여 인원별로 표시합니다. 총점은 kill 횟수 − 포기 횟수이며 kill +1점, 포기 -1점으로 계산합니다. kill 열·점수 안내·포기 기록·확인창의 kill 표시는 숨기고 기록과 총점 계산은 유지합니다.
- 투표: 제목과 선택지 2~12개를 등록합니다. 로그인한 사람마다 한 표를 행사하며 선택을 바꿀 수 있습니다. 작성자·관리자는 마감·재개·삭제할 수 있고 삭제 전 확인합니다.
- 돌림판: 선택지 2~12개를 입력해 추첨합니다. 회전 애니메이션과 최근 20회 결과를 표시합니다. 각 칸은 같은 확률이며 중복 항목을 입력하면 해당 항목의 확률이 높아집니다.

메뉴를 옮겨도 게임 결과와 작성 중인 입력을 유지합니다. 결과·투표는 기존 내용 저장으로 `save/toys`에 보관하며 다른 사용자는 저장된 내용을 새로 불러와 확인합니다. 실시간 게임 서버나 외부 서비스는 사용하지 않습니다. 로컬 파일 실행 시에도 같은 기능을 사용할 수 있습니다.

웹 배포의 스크립트·스타일에는 시작 HTML의 `runtimeResources.version`을 붙여 이전 캐시와 구분합니다. 후속 배포에서 실행 파일이 변경되면 이 버전도 갱신합니다. `file://` 실행 경로에는 버전 쿼리를 붙이지 않습니다.

### 오늘의 식사추천 자료

공공데이터포털의 [음성군 충북혁신도시 일반음식점현황](https://www.data.go.kr/data/15118972/fileData.do)(2026-01-09)을 사용합니다. 이용허락범위 제한 없음으로 공개된 자료입니다. 음성군 맹동면 두성리·동성리의 영업 업소 303곳만 수록하며 진천 지역은 목록·추천에서 제외합니다. 자료 기준일 이후 변동과 실제 휴무·점심 영업은 확인이 필요합니다.

목록과 추천은 로컬 `source/html/toys/meal-data.js`, `meal.js`에서 동작합니다. 추천 버튼을 누를 때마다 전체 303곳에서 무작위로 한 곳을 뽑습니다. 직전에 나온 곳은 연속으로 나오지 않습니다. 검색·메뉴 이동으로 결과가 바뀌지 않으며 결과는 해당 창에서 유지합니다. 외부 지도는 사용자가 링크를 누를 때만 열립니다.

목록 갱신 시 음성군 공식 CSV를 내려받은 뒤 `node prg/scripts/import-restaurants.cjs <음성CSV절대경로>`로 에셋을 다시 생성합니다. CSV 원본·고객 업무 JSON·개인 저장 데이터는 변경하지 않습니다.

### 총연차 자동 계산

멤버 관리에서 등록한 입사일을 연차 정책과 연결하며, 별도 정책을 저장하지 않아도 기본 자동 계산을 사용합니다. 총연차는 입사 기념일과 근속연수별 정책에 따라 계산합니다. 기존 고정 숫자는 보존하지만 자동 계산이 가능하면 이를 가리지 않습니다. 연차 총수 설정에서 직접 입력을 선택하면 수동 총수를 적용하며 자동 계산으로 다시 전환할 수 있습니다. 입사일이 없는 경우에는 입사일 등록이 필요하다는 안내를 표시하고, 명시적으로 자동 적용을 해제한 정책은 유지합니다.

연차 계산 방식 `leaveAllowanceModes`는 개인·연도별로 저장하며 `save/휴가/설정` 이력에 포함합니다. 연차 정책에서 입사일을 수정하면 멤버 정보에도 같은 날짜를 반영합니다. 자동 계산은 기존 정책과 동일하게 개근·출근율 충족을 전제로 하며 근태 예외는 수동 총수로 반영합니다.
