# 워크 플레이스

## 폴더 구성

- `source/html`: 실제 페이지. `source/js`, `source/css`, `source/images`, `source/font`: 로컬 화면 리소스.
- `test`: 개발 샘플, 샘플 생성 도구, 자동 테스트. `test/results`: 검증 결과. 개발 중에는 샘플을 유지합니다.
- `process`: 고객 자료를 읽어 작업한 **우리 공용 업무 데이터**와 변경 불가능한 저장 이력. `process/legacy`는 이전 통합관리 JSON과 백업입니다.
- `dist/users/<사용자 이름>/`: 사용자별 개인 메모·일정의 저장 이력. 이름은 경로에 안전한 형태로 인코딩됩니다.
- `data/request/<과업 ID>/`: 업무요청, 확인, 수정, 전달 이력. 한 과업의 모든 회신을 같은 폴더에 추가 저장합니다.
- `prg`: Edge 독립창 실행, 바로가기, 로컬 서버, 복구·배포 도구. 배포 ZIP은 `prg/releases`.
- `docs`: 사용 방법과 개발·디자인 문서.
- 루트는 실행용 `index.html`과 Git 동작에 필요한 `.gitignore`, `.nojekyll`만 유지합니다. Git 내부 폴더는 숨김 폴더입니다.

고객 원본 JSON은 읽기 전용입니다. 원본 폴더 또는 그 하위 폴더를 저장 위치로 선택할 수 없습니다. 원본 파일은 수정·삭제·이동하지 않습니다. 저장 폴더에는 **프로젝트/공용 저장의 최상위 폴더**를 선택하세요. 프로그램이 그 아래 process, dist, data를 나눠 관리합니다. 세 폴더는 함께 백업해야 합니다.

## Windows 10/11 실행

1. 전체 프로젝트를 고정된 위치에 압축 해제합니다.
2. `prg/Create-Desktop-Shortcut.bat`를 실행하면 바탕화면 바로가기를 만듭니다.
3. 바로가기 또는 `prg/Start-Workplace.bat`로 Edge 앱 창을 실행합니다. 주소 표시줄이나 탭은 표시되지 않습니다.
4. 폴더를 옮긴 뒤에는 바로가기 생성 파일을 다시 실행하세요. 기존 버전의 로컬 서버가 열려 있다면 종료 후 새 버전을 실행하세요.

기본 실행은 Windows PowerShell/.NET의 읽기 전용 로컬 서버 `http://127.0.0.1:49271/source/html/index.html`을 사용합니다. 별도 런타임 설치나 관리자 권한은 필요하지 않습니다. 보안 정책에서 PowerShell·폴더 접근을 차단하면 사내 HTTPS 서버를 사용해야 합니다. `prg/scripts/Start-Workplace.ps1 -Mode File`도 제공하지만 file 모드에서는 브라우저 정책에 따라 폴더 연결 기능이 제한될 수 있습니다. 브라우저 보안을 해제하는 옵션은 사용하지 않습니다.

아이콘은 `source/images/ico/kkulkkkuk.ico`입니다. 바탕화면 바로가기에 적용하며 웹페이지 favicon으로도 연결합니다. 작업 표시줄 고정은 Edge/Windows 정책에 따라 다르고, 실행 창 아이콘이 Edge 아이콘으로 보일 수도 있습니다.

화면 리소스는 실행 시 현재 프로젝트 위치를 기준으로 **절대 URL**을 계산합니다. C 드라이브 경로를 다른 PC에 강제로 고정하지 않습니다. CSS의 폰트·이미지 참조도 해당 스타일시트의 절대 URL 기준으로 브라우저가 해석합니다. CDN이나 외부 디자인 프레임워크는 사용하지 않습니다.

## 원본 읽기와 안전한 공용 저장

폴더 연결 시 원본을 읽고, 저장 폴더의 최신 이력을 읽어 반영합니다. 원본 변경을 즉시 감시하는 방식은 아니며 새로고침/원본 새로 읽기로 다시 확인할 수 있습니다. 기존 사용자 수정값과 가져온 원본을 구분해 유지합니다.

`내용 저장`은 process의 기능별 파일과 dist의 사용자별 파일을 작성한 뒤 process/commits에 최종 이력을 발행합니다. 변경하지 않은 파일은 재사용합니다. 이전 save 폴더와 통합관리 JSON은 읽기만 하고 새 저장부터 새 구조를 사용합니다. 기존 JSON 백업을 process/legacy에 둔 경우에도 읽을 수 있습니다.

동시에 저장하면 기존 버전과 다른지 검사합니다. 충돌한 양쪽 이력은 삭제하지 않고 추가 저장을 중단합니다. 복구 시 모두 편집을 멈춘 후 `prg/scripts/Recover-Save.ps1 -SaveFolder <절대 process 경로>`로 분기를 확인하고 `-Commit <ID>`로 선택합니다. 복구 도구는 모든 분기를 process/recovery에 내보내며 dist 개인 데이터도 함께 읽습니다. 원본 고객 자료와 기존 이력은 수정하지 않습니다.

업무요청은 일반 업무 저장과 별도로 즉시 저장합니다. UUID별 개별 파일로 추가하므로 서로 다른 사람의 동시 회신을 덮어쓰지 않습니다. 이전 process/requests 또는 save/requests가 있으면 읽기 전용으로 함께 표시합니다. 공유 폴더 권한이 있는 사람에게 파일 수준의 접근권한이 생기며, 웹페이지 로그인만으로 파일 자체의 보안을 제공하지는 않습니다.

## 업무요청

- 요청사항은 전체/받은 요청/보낸 요청, 이름·제목·내용 검색, 최신순/과거순 정렬을 제공합니다.
- 왼쪽 작은 별로 즐겨찾기하면 최상단에 표시됩니다. 오른쪽 삭제는 본인의 요청 목록에서만 숨기며 다른 사람과 공용 이력은 유지합니다.
- 요청 확인 시 해당 과업의 확인한 알림이 해제되고 읽은 카드는 회색으로 표시됩니다. 읽음·숨김·즐겨찾기는 브라우저 내 사용자별로 보관됩니다.
- 작성창은 단계/제목 → 팀별 받는 사람 → 내용 → 여러 확인 URL 순서입니다. 받는 사람은 기획/퍼블/디자인/콘텐츠 순이며 직급순·같은 직급은 가나다순입니다.
- 작업 요청/확인 요청/수정 전달/확인 완료/고객 전달을 기록합니다. 같은 과업에 기획·디자인이 각각 회신해도 한 타임라인에서 확인합니다. 고객 전달은 기록 기능이며 실제 고객에게 파일을 보내지는 않습니다.
- URL은 이름과 http/https 주소를 최대 20개 등록합니다. localhost 주소는 보는 사람의 PC를 가리키므로 팀 확인용이면 모두 접근 가능한 내부 서버 주소를 사용하세요.
- 타임라인은 기본 최신순이며 과거순으로 전환할 수 있습니다. 프로필은 현재 선택 이미지와 연동합니다. 약 3초마다 요청을 확인하지만 내용이 같으면 화면을 다시 그리지 않고, 새 내용이 생겨도 스크롤 위치를 보존합니다.
- 샘플 요청은 [샘플]로 표시하며 실제 공유 폴더에 자동 전송하지 않습니다. 샘플 이력을 실제 전송으로 전달하지 않습니다.

## 화면과 권한

첫 화면은 홈입니다. 큰 페이지 제목 영역을 없애고 필요한 작업 버튼만 유지합니다. 홈 달력에는 본인 프로젝트와 개인 일정이 표시되며 전체/프로젝트/개인메모 필터를 제공합니다. 진행 중 과업과 나의 일정은 약 3개 분량 높이이며 업무 표 안쪽에만 스크롤을 둡니다. 팀 브리핑은 고정된 영역 안에서 내용을 자연스럽게 표시합니다.

브리핑 오른쪽 아래를 다섯 번 클릭하면 색상·크기·위치·좌우반전·X/Y/Z 회전을 미리보고 조정합니다. 사용자·캐릭터·기본형/대두형별로 브라우저에 독립 저장합니다. 모드를 바꿔도 제목/버튼 좌표는 같습니다.

전체관리자 설정에서 직급 추가·이름 변경·제거·순서 조정이 가능합니다. 직급 이름을 바꾸면 해당 인원에도 반영하고, 제거한 직급은 미지정으로 표시합니다. 내용 저장으로 공용 반영하세요. 진행률·상태는 관리자를 포함해 본인 담당 업무만 바꿀 수 있습니다.

접속 프로필은 공용 저장 폴더의 별도 임시 접속 파일을 사용합니다. 업무관리의 다른 사람 커서는 같은 보기·검색 조건에서 약 1.5초 간격으로 표시합니다. 공용 폴더/네트워크·브라우저 백그라운드 상태에 따라 지연될 수 있으며 실시간 서버처럼 매 프레임 동기화되지는 않습니다.

WBS는 사용자 요청으로 보류했습니다.

## 개발 검증과 배포

프로젝트 루트에서 `node --test test/*.test.cjs`로 검증합니다. Node는 개발 검증용이며 실제 사용자는 설치할 필요가 없습니다. 개발 서버는 `node prg/server.cjs` 또는 `npm --prefix prg start`입니다.

배포 파일: `powershell -NoProfile -File prg/scripts/package-offline.ps1`. 결과는 `prg/releases/manager-board-offline.zip`이며 process/dist/data의 실제 데이터, 백업, 계정, Git 이력은 포함하지 않습니다. 개발 확인용 샘플 스크립트는 test 아래에 포함됩니다. 사용자가 요청하기 전까지 개발 샘플을 제거하지 않습니다. 이후 test를 제거해도 기본 앱은 실행됩니다.

Git에는 검증 완료한 소스만 커밋/푸시합니다. process, dist, data, save, 샘플 JSON, 로컬 백업은 제외합니다. 로컬 서버도 해당 저장 폴더와 JSON을 HTTP로 제공하지 않습니다.
