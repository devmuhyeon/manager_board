# 워크 플레이스 · 통합 업무관리

인터넷 연결이나 설치 없이 사용하는 HTML 기반 프로토타입입니다. `index.html`을 Edge 또는 Chrome으로 열면 시작합니다. 개발 미리보기는 `npm start` 후 `http://127.0.0.1:4173`에서 확인합니다.

## 시작하기

1. 첫 화면에서 Z 자료 폴더, 원본 `요청관리.json`, Y 저장 폴더를 연결합니다. 기준 자료 폴더는 `Z:\고용24 디자인파트 요청관리\디자인파트요청관리\`입니다. 요청관리 JSON이 다른 위치에 있으면 별도로 선택하세요. Y의 구체적인 저장 폴더도 직접 선택합니다.
2. 폴더 연결 전에 시작하려면 검은색 **연결은 나중에, 로그인 먼저** 버튼을 누릅니다. 나중에 왼쪽 아래 폴더 재연결에서 연결하세요.
3. 팀과 이름을 선택합니다. 최초 로그인 때에만 비밀번호(6자 이상)와 확인란을 입력합니다. 로그인에서는 직급을 선택하지 않습니다. 로그인 후 왼쪽 아래에는 이름과 직급이 표시됩니다.
4. 로그인 정보 기억을 선택하면 마지막 로그인 팀·이름·비밀번호를 현재 PC의 같은 브라우저에 보관합니다. 로그아웃해도 유지되며, 설정에서 지울 수 있습니다. 다른 컴퓨터에는 전달하지 않습니다.
5. 변경 후 상단 **내용 저장**을 누르면 선택한 Y 폴더의 `통합관리 대시보드.json`에 반영합니다. 연결 전에는 브라우저 임시 저장만 됩니다.

## 홈과 설정

- 상단 한 줄: 날짜, 새로고침, 내용 저장, 설정. 폴더 상태·재연결은 왼쪽 아래 사용자 정보 위에 있습니다.
- 홈: 이번 주·다음 주 일정(월~일), 미완료 프로젝트 마감 D-day, 다가오는 팀원 휴가, 개인 메모.
- 날짜 없는 메모와 상세 본문은 본인 화면에 표시합니다. 날짜 지정 일정의 제목·시간·완료 상태는 팀장도 조회합니다. 모든 데이터는 같은 통합관리 JSON에 보관되므로 파일 접근 권한 자체를 분리하는 기능은 아닙니다.
- 인원관리 → 팀장 지정: 각 팀의 재직자 중 팀장을 선택합니다. 팀장은 같은 팀의 일정을 조회하고 소속 팀원의 휴가를 등록·수정·삭제합니다. 전체관리자와 팀관리자는 모든 재직자의 휴가를 관리하고, 일반 팀원은 본인 휴가만 변경합니다. 팀장 지정과 입사·퇴사 관리, 개별 비밀번호 초기화는 전체관리자와 팀관리자만 가능합니다. 팀관리자 지정·해제는 현재 전체관리자만 가능합니다. 기존 데이터의 초기 전체관리자는 김무현이며, 설정에서 다른 재직자에게 이전할 수 있습니다. 이전 적용 후 내용 저장으로 공용 JSON에 반영합니다. 팀장은 인원관리 탭에서 소속 팀원의 휴가를 관리하며 입사·퇴사 관리는 사용할 수 없습니다.
- 휴가: 연차·오전 반차·오후 반차·기타 휴가, 시작·종료 날짜. 반차는 하루 단위입니다. 전체 휴가 관리에서 지난 휴가도 확인합니다.
- 인원관리 탭: 입사·재입사 등록, 퇴사 시 자료 보관/제거 선택. 퇴사자는 로그인 대상과 팀장 지정에서 제외합니다. 제거 시 개인 메모·휴가·작성 작업내역·단독 담당 업무를 제거하며 다른 사람의 공동 업무는 보존합니다. 원본 파일과 자유 형식 원문 사본은 변경하지 않습니다.
- 주간 업무보고 탭 순서: 전체 → 팀 → 개인.
- 프리텐다드 폰트와 jQuery는 로컬 파일로 포함합니다. 메인 색상은 `--primary_blue_50: #3F58D4`입니다. 글꼴 라이선스는 `font/LICENSE.txt`에 있습니다.

## 기존 시트 구조

구분1 / 구분2 / 과업명 / 세부유형 / 담당자 / 고객명 / 요청완료일 / 시작일 / 마감일 / 진행상태 / 비고를 지원합니다.

한 과업 아래에 기획·디자인·퍼블 등의 담당 업무를 여러 개 등록합니다. 각 담당 업무의 담당자·일정·상태·비고를 따로 관리하며, 과업 전체 상태는 담당 업무 상태에서 계산합니다. 모든 담당 업무가 완료되면 과업이 완료됩니다. 과업 마감일은 담당 업무 중 가장 늦은 마감일입니다.

개인·팀·전체 화면은 같은 과업을 공유합니다. 공동 과업은 각 담당자의 개인 화면과 소속 팀 화면에 표시하며, 전체 건수는 중복을 제외합니다. 분류별 보기는 분류 1~3을 기준으로 묶어 담당 업무별 행을 표시합니다. 업무·고객·주간보고 탭에서 분류별/과업별을 선택할 수 있으며 기본은 분류별입니다.

주간보고는 상세 화면에서 추가한 **작업일·작업자·작업 내용**을 취합합니다. 기존 자유 형식 비고는 유지하되, 그 안의 날짜를 자동 해석하지 않습니다. 엑셀 내보내기는 현재 범위와 기간·검색·상태 필터를 반영하며, 업무 목록과 날짜별 작업 내역을 별도 시트로 제공합니다. 주간보고의 기간은 작업일, 일반 대시보드의 기간은 선택한 날짜 기준입니다.

## 원본 보호와 저장

- 원본 `요청관리.json`에는 쓰기·삭제 동작이 없습니다. 원본 폴더는 읽기 권한만 요청합니다.
- 쓰기 대상은 사용자가 선택한 저장 폴더의 `통합관리 대시보드.json`으로 고정됩니다.
- 가져온 원본과 통합관리 수정값을 분리하여 재수입 시 수정값·작업 내역·직접 등록 과업을 보존합니다.
- 원본에서 사라진 항목은 자동 삭제하지 않습니다.
- 저장 직전 파일 변경을 확인하고, 마지막 읽기 이후 변경됐다면 저장을 중단합니다. 완전한 동시 편집 잠금은 아니므로 여러 사람이 동시에 저장하는 용도로는 서버 방식의 후속 구현이 필요합니다.
- 비밀번호는 사용자별 무작위 salt와 PBKDF2-SHA256 150,000회로 해시하여 저장합니다. 공용 파일에 접근할 수 있는 사용자를 차단하는 서버 인증은 아닙니다.
- 폴더 연결은 현재 브라우저의 IndexedDB에 기억합니다. 다시 열 때 접근 권한이 유지되면 자동 연결하며, 권한이 만료되면 **기억된 폴더 접근 허용**으로 재허용합니다. 처음에는 브라우저에서 폴더를 직접 선택해야 합니다. HTML이 경로 문자열만으로 디스크 접근 권한을 얻을 수는 없습니다. 브라우저 데이터 삭제·다른 브라우저·주소 변경 시 다시 연결해야 합니다.
- 기억할 로그인 비밀번호는 현재 브라우저의 비추출 AES-GCM 키로 암호화하여 기기 내부에 보관합니다. 공유 파일에는 로그인 검증용 해시만 저장합니다.
- 새로고침은 연결된 요청관리 JSON 전체를 다시 읽어 새 요청·변경사항을 가져옵니다. 통합관리 수정값과 직접 등록한 프로젝트는 유지합니다. 원본에서 사라진 항목을 자동 삭제하지 않습니다.

## 실제 JSON 연결 전 확인할 사항

현재 가져오기는 이전 대화에서 확인된 한글 필드명과 일반적인 별칭을 지원합니다. `프로젝트명`, `과업명`, `요청제목`, `제목` 및 `담당자_기획`, `담당자_디자인`, `담당자_퍼블` 등을 읽습니다. 파일 최상위 배열 또는 `요청목록`, `요청관리`, `requests`, `projects`, `data` 배열을 지원합니다.

사진에 있는 전체 원본 JSON 구조는 확보하지 못했으므로 실제 파일로 필드 매핑 확인이 필요합니다. 제목 또는 ID가 잘못된 항목이 있으면 전체 가져오기를 중단하여 부분 반영을 피합니다. ID가 없을 때에는 제목·요청팀·요청자·요청일 조합으로 식별하므로, 재수입의 안정성을 위해 원본의 고정 ID 사용을 권장합니다.

구글시트 스크린샷은 화면·항목 구조에 반영했으며, 사진의 실제 업무를 전체 전사하거나 구글시트에 연결한 상태는 아닙니다. HWP는 이번 범위에 포함하지 않습니다.

검증: `node --test tests/*.test.cjs` (또는 npm이 설치된 환경의 `npm test`). 파일 읽기·쓰기·자동 재연결은 모의 핸들로도 검증합니다. 실제 내부망 Z·Y 드라이브의 권한 유지 여부는 사용 환경에서 확인해야 합니다.

## 홈 개인 배치와 남은 일수

메모 & 일정이 기본적으로 맨 위에 표시됩니다. 홈의 배치 순서 설정에서 메모, 이번 주, 다음 주, 프로젝트 마감, 휴가, 업무 현황·목록을 각각 이동하고 저장할 수 있습니다. 배치는 사용자별로 임시 저장되며 내용 저장 시 통합관리 JSON에도 반영됩니다.

7칸과 D-day는 각 일정의 날짜, 프로젝트 마감일, 휴가 시작일까지 남은 일수를 표시합니다. 주간 일정 제목에는 표시하지 않습니다. 7일을 넘으면 7칸을 채우고 숫자는 실제 일수를 표시하며, 지난 날짜는 D+숫자로 표시합니다.
