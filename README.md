# 워크 플레이스 · 통합 업무관리

## Windows 바탕화면 앱 실행 (2026-11-12)

1. 프로젝트 또는 배포 ZIP 전체를 PC의 고정 폴더에 압축 해제합니다. HTML만 따로 옮기지 마세요.
2. `Create-Desktop-Shortcut.bat`를 한 번 실행합니다. 바탕화면에 **Workplace** 바로가기가 만들어집니다.
3. 바로가기를 더블클릭합니다. Windows 기본 PowerShell이 `127.0.0.1:49271`에 정적 파일만 제공하고, Edge를 `--app="http://127.0.0.1:49271/html/index.html"`로 실행합니다. 주소 표시줄·탭이 없는 독립 창입니다. 관리자 권한, Node, Electron 설치가 필요하지 않습니다.
4. 원본 폴더는 읽기 권한, 공용 저장 폴더는 읽기/쓰기 권한으로 연결합니다. Edge가 권한을 다시 요청하면 해당 폴더만 허용합니다. 같은 공용 저장 폴더를 팀원이 함께 선택합니다.

바로가기 없이 `Start-Workplace.bat`로도 실행할 수 있습니다. 폴더를 옮기면 새 위치에서 바로가기 생성 BAT를 다시 실행하세요. 하위 파일은 스크립트 위치를 기준으로 찾습니다. 이전 위치의 로컬 서버가 떠 있으면 재부팅 후 실행하세요. 로컬 서버는 로그아웃/재부팅까지 백그라운드에서 유지됩니다. 같은 주소를 유지하므로 동일 Edge 프로필의 임시 저장과 설정을 계속 사용합니다. 기존 `file://`·GitHub Pages·4173 포트에서 사용한 브라우저 저장과는 별개이므로, 이동 전 내용 저장 또는 JSON 백업 후 새 실행 환경에서 폴더를 연결하세요.

ICO는 `images/ico/kkulkkkuk.ico`를 그대로 사용합니다. 바로가기 아이콘과 HTML favicon에 적용했습니다. 작업 표시줄에서 실행된 창을 우클릭해 고정할 수 있으나, Edge 앱 모드만으로는 별도 앱 식별자·작업 표시줄 아이콘·고정 후 실행 인수가 Windows 버전마다 동일하게 보장되지 않습니다. 로컬 서버 시작까지 보장하는 실행 경로는 제공한 바탕화면 바로가기입니다. 별도 앱 고정이 필요한 경우 회사 정책이 허용하면 Edge의 ‘이 사이트를 앱으로 설치’ 기능을 사용할 수 있습니다. [Microsoft 안내](https://support.microsoft.com/en-us/edge/install-manage-or-uninstall-apps-in-microsoft-edge).

PowerShell 실행 자체가 회사 정책으로 차단되면 스크립트가 정책을 해제하지 않습니다. 실행 명령의 `-ExecutionPolicy Bypass`는 해당 프로세스에만 적용되고 조직 정책을 변경하지 않습니다. 이 경우 내부 HTTPS 서버에 배포하거나 IT 담당자의 허용이 필요합니다.

### file 실행과 내부 서버 선택

서버 없이 파일 주소로 실행하려면 다음 명령으로 바로가기를 다시 만듭니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Create-Desktop-Shortcut.ps1 -Mode File
```

`file://`는 브라우저/조직 정책에 따라 파일 선택·권한 유지·저장소 동작이 다를 수 있어 기본은 localhost 방식입니다. 브라우저 보안을 끄는 플래그는 사용하지 않습니다. 파일 선택 API는 보안 컨텍스트와 사용자 클릭이 필요하고, 저장된 파일 핸들도 매 실행 권한을 확인해야 합니다. [Chromium 공식 설명](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access), [보안 컨텍스트 표준](https://www.w3.org/TR/secure-contexts/).

내부 HTTPS 웹 서버가 있으면 실행용 파일만 배포하고 `scripts/Create-Desktop-Shortcut.ps1 -ServerUrl "https://내부주소/html/index.html"`을 사용합니다. 공용 save 폴더는 웹 공개 폴더 밖에 둡니다. 일반 사내 HTTP 주소는 파일 선택 API가 차단될 수 있습니다. 제공한 로컬 서버는 루프백에만 연결하고 JSON·save·Git·문서를 공개하지 않으며 쓰기 API도 없습니다.

CDN 의존성을 검사했습니다. jQuery·Pretendard·Tossface·캐릭터·CSS·ICO는 모두 프로젝트 안의 상대경로입니다. 코드의 라이선스 URL과 XLSX XML 네임스페이스는 외부 다운로드가 아닙니다. 사용자가 등록한 외부 업무 링크는 해당 네트워크 접근이 별도로 필요합니다.

## 기능별 저장과 동시 사용

저장 폴더를 연결하면 그 안에 `save`를 만들고 첫 **내용 저장**부터 다음 구조를 사용합니다. 브리핑·주간 일정·고객별 조회는 같은 과업 자료를 참조하므로 중복 저장하지 않습니다.

```text
선택한 공용 저장 폴더/
  save/
    work/       과업·담당 업무·진행률
    memo/       개인 메모와 일정
    leave/      휴가와 연차
    board/      게시글
    people/     인원과 계정
    assets/     추가한 캐릭터 이미지
    settings/   공통 설정과 가져오기 정보
    commits/    완성된 저장 묶음의 연결 정보
    recovery/   충돌 복구 시 내보낸 각 버전
```

바뀐 모듈만 새 UUID JSON으로 쓰고, 변경 없는 모듈은 이전 파일을 재사용합니다. 모든 모듈 쓰기가 끝난 뒤 저장 묶음을 공개하므로 중간 실패 때 섞인 자료를 정상 저장처럼 읽지 않습니다. 기존 `통합관리 대시보드.json`은 최초 이전용으로 읽기만 하고 수정·삭제하지 않습니다. 새 저장 이력이 생기면 save가 기준입니다. **팀 전체가 새 버전으로 전환한 후 사용하세요. 구버전과 신버전을 동시에 저장에 사용하지 마세요.**

- **접속 시 고객 원본 갱신:** 기억된 폴더의 접근 권한이 유효하면 시작 시 최신 원본을 다시 읽고, 통합관리에서 수정한 내용은 유지합니다. 권한이 만료되면 재허용 후 읽습니다. ‘연결은 나중에’로 시작한 경우에는 연결 전까지 임시 자료입니다. 접속 중 계속 자동 감시하는 방식은 아니므로 새 고객 요청은 상단 새로고침으로 반영합니다.
- **10명 동시 저장:** 먼저 저장된 변경이 발견되면 덮어쓰지 않고 중단합니다. 확인 이후 정확히 동시에 저장하는 경우에도 서로 다른 이력 파일을 쓰므로 상대 파일을 덮어쓰지 않습니다. 이력이 두 갈래가 되면 충돌을 알리고 읽기/추가 저장을 차단합니다. 자동 병합은 하지 않습니다. 자신의 수정은 JSON 백업으로 보존하세요. 서버 데이터베이스처럼 트랜잭션 잠금을 제공하는 구조는 아닙니다.
- **고객 JSON:** 원본 핸들은 읽기만 사용합니다. 저장 대상은 별도로 선택한 공용 폴더의 save와 접속 현황 폴더뿐입니다. 원본 폴더와 그 하위 폴더를 저장 대상으로 선택하지 못하게 검사합니다. 원본 JSON으로 내보내거나 덮어쓰는 기능은 없습니다.

### 충돌 복구

먼저 모두 저장을 멈추고 각자의 변경사항을 JSON 백업합니다. 담당자가 아래 명령으로 충돌 이력의 작성자·시간·ID를 확인합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Recover-Save.ps1 -SaveFolder "Y:\팀저장\save"
```

유지할 이력을 정한 후 같은 명령에 `-Commit "선택한 이력 ID"`를 붙입니다. 도구는 모든 충돌 버전을 `save/recovery/`에 통합 JSON으로 먼저 보존한 뒤 선택 버전을 기준으로 새 복구 이력을 만듭니다. 다른 버전의 수정사항은 백업과 비교해 다시 반영합니다. 기존 이력은 삭제하지 않습니다. 모두 공용 자료를 다시 읽은 뒤 작업을 재개하세요.

save 전체를 함께 백업하세요. 개별 JSON을 임의 삭제하면 이전 이력이 참조하는 자료가 사라집니다. 기능별 분리는 변경 없는 데이터를 매번 다시 쓰지 않도록 한 것이며, 전체 과업을 브라우저에서 읽는 구조까지 바꾸지는 않습니다. 이력은 누적되므로 저장 공간과 백업 주기를 관리해야 합니다. 실제 사내 공유 드라이브의 권한·지연·동기화 특성은 그 환경에서 최종 확인해야 합니다.

브리핑 커스텀은 **브라우저 내 사용자 이름 + 캐릭터 + 기본형/대두형**별로 저장합니다. 각 모드의 ‘만 저장’ 버튼은 다른 모드 설정을 덮어쓰지 않습니다. ‘두 모드 저장 후 닫기’는 둘 다 저장합니다. 다른 PC로 커스텀 설정이 자동 동기화되지는 않습니다.

## 독립 실행 및 내부망 이동

추가 패키지 설치가 필요 없는 HTML/CSS/JavaScript 앱입니다. Windows 10/11에서는 아래 바탕화면 실행 방법을 사용하세요. Node는 개발 검증용이며 일반 사용자 실행에는 필요하지 않습니다.

기존 Neutral 디자인의 간격·색상·버튼 스타일을 참고해 `source/workplace-tokens.css`와 `source/workplace-components.css`로 독립 구성했습니다. Astryx·React·node_modules는 사용하지 않습니다. 디자인 참고의 원래 MIT 고지는 `source/NEUTRAL-DESIGN-LICENSE.txt`에 보존합니다.

## 시작하기

1. 첫 화면에서 Z 자료 폴더, 원본 `요청관리.json`, Y 저장 폴더를 연결합니다. 기준 자료 폴더는 `Z:\고용24 디자인파트 요청관리\디자인파트요청관리\`입니다. 요청관리 JSON이 다른 위치에 있으면 별도로 선택하세요. Y의 구체적인 저장 폴더도 직접 선택합니다.
2. 폴더 연결 전에 시작하려면 검은색 **연결은 나중에, 로그인 먼저** 버튼을 누릅니다. 나중에 왼쪽 아래 폴더 재연결에서 연결하세요.
3. 팀과 이름을 선택합니다. 최초 로그인 때에만 비밀번호(6자 이상)와 확인란을 입력합니다. 로그인에서는 직급을 선택하지 않습니다. 로그인 후 왼쪽 아래에는 이름과 직급이 표시됩니다.
4. 로그인 정보 기억을 선택하면 마지막 로그인 팀·이름·비밀번호를 현재 PC의 같은 브라우저에 보관합니다. 로그아웃해도 유지되며, 설정에서 지울 수 있습니다. 다른 컴퓨터에는 전달하지 않습니다.
5. 변경 후 상단 **내용 저장**을 누르면 선택한 Y 폴더의 `save/` 아래 기능별 JSON에 반영합니다. 연결 전에는 브라우저 임시 저장만 됩니다.

## 홈과 설정

- 상단 한 줄: 원본·저장 연결 상태, 날짜, 새로고침, 내용 저장, 설정.
- 홈: 이번 주·다음 주 일정(월~일), 미완료 프로젝트 마감 D-day, 다가오는 팀원 휴가, 개인 메모.
- 날짜 없는 메모와 상세 본문은 본인 화면에 표시합니다. 날짜 지정 일정의 제목·시간·완료 상태는 팀장도 조회합니다. 모든 데이터는 같은 공용 저장 폴더에 보관되므로 파일 접근 권한 자체를 분리하는 기능은 아닙니다.
- 인원관리 → 팀장 지정: 각 팀의 재직자 중 팀장을 선택합니다. 팀장은 같은 팀의 일정을 조회하고 소속 팀원의 휴가를 등록·수정·삭제합니다. 전체관리자와 팀관리자는 모든 재직자의 휴가를 관리하고, 일반 팀원은 본인 휴가만 변경합니다. 팀장 지정과 입사·퇴사 관리, 개별 비밀번호 초기화는 전체관리자와 팀관리자만 가능합니다. 팀관리자 지정·해제는 현재 전체관리자만 가능합니다. 기존 데이터의 초기 전체관리자는 김무현이며, 설정에서 다른 재직자에게 이전할 수 있습니다. 이전 적용 후 내용 저장으로 공용 JSON에 반영합니다. 팀장은 인원관리 탭에서 소속 팀원의 휴가를 관리하며 입사·퇴사 관리는 사용할 수 없습니다.
- 휴가: 연차·오전 반차·오후 반차·기타 휴가, 시작·종료 날짜. 반차는 하루 단위입니다. 전체 휴가 관리에서 지난 휴가도 확인합니다.
- 인원관리 탭: 입사·재입사 등록, 퇴사 시 자료 보관/제거 선택. 퇴사자는 로그인 대상과 팀장 지정에서 제외합니다. 제거 시 개인 메모·휴가·작성 작업내역·단독 담당 업무를 제거하며 다른 사람의 공동 업무는 보존합니다. 원본 파일과 자유 형식 원문 사본은 변경하지 않습니다.
- 주간 업무보고 탭 순서: 전체 → 팀 → 개인.
- 프리텐다드 폰트와 jQuery는 로컬 파일로 포함합니다. 메인 색상은 `--primary_blue_50: #3F58D4`입니다. 글꼴 라이선스는 `font/LICENSE.txt`에 있습니다.

## 기존 시트 구조

구분1 / 구분2 / 과업명 / 세부유형 / 담당자 / 고객명 / 요청완료일 / 시작일 / 마감일 / 진행상태 / 비고를 지원합니다.

한 과업 아래에 기획·디자인·퍼블 등의 담당 업무를 여러 개 등록합니다. 각 담당 업무의 담당자·일정·상태·비고를 따로 관리하며, 과업 전체 상태는 담당 업무 상태에서 계산합니다. 모든 담당 업무가 완료되면 과업이 완료됩니다. 과업 마감일은 담당 업무 중 가장 늦은 마감일입니다.

개인·팀·전체 화면은 같은 과업을 공유합니다. 공동 과업은 각 담당자의 개인 화면과 소속 팀 화면에 표시하며, 전체 건수는 중복을 제외합니다. 분류별 보기는 분류 1~3을 기준으로 묶어 담당 업무별 행을 표시합니다. 업무·고객·주간보고 탭에서 분류별/과업별을 선택할 수 있으며 기본은 분류별입니다.

주간보고는 상세 화면에서 추가한 **작업일·작업자·작업 내용**을 취합합니다. 기존 자유 형식 비고는 유지하되, 그 안의 날짜를 자동 해석하지 않습니다. 엑셀 내보내기는 현재 범위와 기간·검색·상태 필터를 반영하며, 업무 목록과 날짜별 작업 내역을 별도 시트로 제공합니다. 주간보고의 기간은 작업일, 일반 대시보드의 기간은 선택한 날짜 기준입니다.

## 원본 보호와 저장

- 원본 `요청관리.json`에는 쓰기·삭제 동작이 없습니다. 원본 폴더는 읽기 권한만 요청합니다.
- 업무 저장은 선택한 저장 폴더의 `통합관리 대시보드.json`에만 반영합니다. 접속 상태는 같은 폴더의 `.workboard-presence` 아래 세션별 임시 파일로 별도 공유합니다.
- 가져온 원본과 통합관리 수정값을 분리하여 재수입 시 수정값·작업 내역·직접 등록 과업을 보존합니다.
- 원본에서 사라진 항목은 자동 삭제하지 않습니다.
- 저장 직전 파일 변경을 확인하고, 마지막 읽기 이후 변경됐다면 저장을 중단합니다. 완전한 동시 편집 잠금은 아니므로 여러 사람이 동시에 저장하는 용도로는 서버 방식의 후속 구현이 필요합니다.
- 비밀번호는 사용자별 무작위 salt와 PBKDF2-SHA256 150,000회로 해시하여 저장합니다. 공용 파일에 접근할 수 있는 사용자를 차단하는 서버 인증은 아닙니다.
- 폴더 연결은 현재 브라우저의 IndexedDB에 기억합니다. 다시 열 때 접근 권한이 유지되면 자동 연결하며, 권한이 만료되면 **기억된 폴더 접근 허용**으로 재허용합니다. 처음에는 브라우저에서 폴더를 직접 선택해야 합니다. HTML이 경로 문자열만으로 디스크 접근 권한을 얻을 수는 없습니다. 브라우저 데이터 삭제·다른 브라우저·주소 변경 시 다시 연결해야 합니다.
- 기억할 로그인 비밀번호는 현재 브라우저의 비추출 AES-GCM 키로 암호화하여 기기 내부에 보관합니다. 공유 파일에는 로그인 검증용 해시만 저장합니다.
- 새로고침은 연결된 요청관리 JSON 전체를 다시 읽어 새 요청·변경사항을 가져옵니다. 통합관리 수정값과 직접 등록한 프로젝트는 유지합니다. 원본에서 사라진 항목을 자동 삭제하지 않습니다.

## 실제 JSON 연결 전 확인할 사항

현재 가져오기는 이전 대화에서 확인된 한글 필드명과 일반적인 별칭을 지원합니다. `프로젝트명`, `과업명`, `요청제목`, `제목` 및 `담당자_기획`, `담당자_디자인`, `담당자_퍼블` 등을 읽습니다. 파일 최상위 배열 또는 `요청목록`, `요청관리`, `requests`, `projects`, `data` 배열을 지원합니다.

사진에 있는 전체 원본 JSON 구조는 확보하지 못했으므로 실제 파일로 필드 매핑 확인이 필요합니다. 제목 또는 ID가 잘못된 항목이 있으면 전체 가져오기를 중단하여 부분 반영을 피합니다. ID가 없을 때에는 제목·요청팀·요청자·요청일 조합으로 식별하므로, 재수입의 안정성을 위해 원본의 고정 ID 사용을 권장합니다.

구글시트 스크린샷은 화면·항목 구조에 반영했으며, 사진의 실제 업무를 전체 전사하거나 구글시트에 연결한 상태는 아닙니다. HWP는 이번 범위에 포함하지 않습니다.

검증: `node --test tests/*.test.cjs` (또는 npm이 설치된 환경의 `npm test`). 파일 읽기·쓰기·자동 재연결은 모의 핸들로도 검증합니다. 실제 내부망 Z·Y 드라이브의 권한 유지 여부는 사용 환경에서 확인해야 합니다.

## 공용 폴더 접속 현황

같은 공용 저장 폴더에 쓰기 권한으로 연결한 로그인 사용자들이 약 10초 간격으로 서로 표시됩니다. 종료 후 마지막 갱신에서 40초가 지나면 제외됩니다. 파일 동기화 지연과 절전/브라우저 백그라운드 제한에 따라 반영이 늦어질 수 있습니다. 접속 정보는 업무 JSON 및 Git에 포함하지 않습니다.

실행 파일 ZIP은 `powershell -NoProfile -File scripts/package-offline.ps1` 또는 `npm run package`로 생성합니다. 결과는 `dist/manager-board-offline.zip`이며 실제 업무 JSON·계정·접속 파일·Git 이력·개발 의존성을 포함하지 않습니다.

브리핑 배너는 두 모드 모두 1656×258 기준입니다. 소개 영역 x360/y46, 업무 관리 버튼 x360/y171, 토글 x1532/y34, 통계 카드 x954/y68을 공통 사용합니다. 화면이 작으면 동일 비율로 축소합니다. 이미지 크기·위치·색상은 사용자/캐릭터/모드별 설정을 따릅니다.

## 캐릭터 추가와 개발 브리핑

설정 → 캐릭터 선택 → 캐릭터 추가에서 이름과 PNG/JPG/WebP 이미지를 등록합니다. 최대 10MB 원본을 512px 이내 이미지로 정규화하고 새 캐릭터를 바로 선택합니다. 새 브리핑의 기본 테마는 핑크입니다. 내용 저장을 누르면 이미지도 save/assets에 포함되며 같은 공용 자료를 불러온 PC에서 사용할 수 있습니다. 원본 고객 폴더에는 쓰지 않습니다.

개발 단계에는 최초 진입 또는 아직 샘플이 없는 저장 자료를 읽을 때 샘플 과업 36개·게시글 36개·휴가 20개·인원별 메모 12개를 기존 자료에 추가합니다. 기존 계정·인원·선택 캐릭터·작성 내용을 대체하지 않습니다. 시작 시 샘플을 삭제하던 처리를 제거했으며, 별도 요청 전까지 샘플을 유지합니다. 추가된 샘플은 내용 저장으로 공용 자료에 반영합니다.

브리핑은 대시보드와 달력을 각각 전체 너비로 표시하고, 아래에 진행 중 과업/나의 일정, 팀 브리핑/팀 휴가 일정을 2열로 배치합니다. 좁은 화면에서는 같은 순서로 1열이 됩니다. 직접 지정한 padding과 margin은 4px 배수로 통일했습니다.
